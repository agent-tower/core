# 项目与任务

Project 和 Task 是 Agent Tower 的入口对象。

## Project

Project 表示一个本地 Git 仓库。

它保存：

- 仓库路径
- 主分支
- 初始化脚本
- 需要复制到 workspace 的本地配置
- 快捷命令
- 归档状态

Project 不复制你的主仓库。只有创建 workspace 时，系统才会基于这个仓库创建 git worktree。

## Task

Task 是具体工作项。它属于某个 Project，并在看板上流转。

Task 状态：

| 状态 | 含义 |
| --- | --- |
| `TODO` | 待执行 |
| `IN_PROGRESS` | 有 session 正在执行，或任务处于进行中 |
| `IN_REVIEW` | agent 已完成，等待人工审查 |
| `DONE` | 已合并或确认完成 |
| `CANCELLED` | 已取消 |

任务还支持四档优先级：低（`-1`）、普通（`0`，默认）、高（`1`）和紧急（`2`）。任务进入 `IN_REVIEW` 后，看板会按优先级从高到低排列；同一优先级沿用任务在该状态中的位置。

优先级可以在创建任务时设置，也可以从任务详情或看板任务的操作菜单中修改。

创建任务时，Agent 列表会优先显示可用配置，并按最近成功使用的时间排序；最近使用记录保存在当前浏览器中。每项右侧的盾牌图标表示执行权限，悬停可查看权限名称；不可用配置仍会显示原因。

创建栏右侧的双图标固定用于切换单人模式和团队模式。左侧配置在空间不足时从右向左收进“更多”，展开后仍可查看和修改当前值；隐藏配置有修改时，“更多”显示提示点。

工作树模式和团队模式可以选择 **基础分支**，默认使用项目配置，支持搜索本地已有分支。长分支名在创建栏中省略，展开可查看完整名称。本次选择随任务保存，稍后启动或创建团队主工作区仍沿用它；切换项目或成功创建任务后，创建栏恢复项目默认值。本地模式不显示基础分支。

任务工作树从所选分支创建，并以它作为差异比较、rebase 和合并的基础。团队成员工作区仍从团队主工作区分支创建。若分支已被删除，创建工作区会明确报错，不会改用其他分支。

## 子任务

从任务的右键菜单，或任务详情右上角 `···` 菜单选择 **创建子任务**。子任务与父任务属于同一项目，支持主任务 → 子任务 → 孙任务，共三级。主任务和子任务都可以继续创建下级；孙任务没有创建下级的入口，API 和 MCP 也会拒绝第四级。各层任务都可以使用单人或团队模式。

工作树模式下，子任务、孙任务默认从直接父任务的工作分支创建，并以该分支作为差异比较、更新和合并目标。创建栏可以调整基础分支，创建后保存本次选择。父任务还没有工作分支时，使用它保存的基础分支，再回退到项目默认值。本地模式沿用项目目录，不创建独立工作分支。

侧栏只将父任务作为顶层任务展示。主任务和子任务右侧的图标显示直属子任务数量，点击后逐层展开或收起；点击任务标题仍然打开详情。子任务显示自己的状态，父任务所在分组由父任务状态决定。任务详情右侧有独立的 **子任务** 标签，与变更、编辑器、终端和预览并列；打开后可查看列表、创建子任务或返回父任务，不占用聊天区顶部空间。手机端从 **工作区 → 子任务** 进入。搜索结果也会标明所属父任务。选中孙任务时会展开主任务和子任务，即使它们位于其他分页。

父子任务分别运行、停止和完成，状态不会互相推进，会话和上下文也不会自动共享。合并到父任务工作目录前，需要结束该目录的活动会话和后台服务，并处理未提交的修改。父任务完成后，仍被子任务或孙任务作为基础分支使用的分支会保留。

删除确认框统计全部后代：删除主任务包含其子任务和孙任务，删除子任务包含其孙任务，删除孙任务只清理自身。确认后会停止该范围内的 Agent 和后台服务，按孙任务、子任务、主任务的顺序清理各自的工作目录和工作分支。若确认期间后代数量发生变化，需要重新确认删除范围。

任务会先从列表移除，资源清理在后台静默进行；仅清理失败时显示通知并提供重试。刷新同一浏览器标签页后仍会跟踪未完成的清理。

## 交接笔记

任务详情右侧的 **交接笔记** 用于记录当前进展、已完成工作、关键决策、验证结果和下一步。手机端从 **工作区 → 交接笔记** 进入。任务尚未创建工作区时也可以编辑笔记。

点击 **编辑** 修改 Markdown，点击 **保存** 或按 `Ctrl/Cmd + Enter` 保存；**复制** 可以将内容交给其他人或 AI。同一任务的不同会话和工作区共用笔记，子任务各自独立。详细执行过程继续保留在原有会话历史中。

Agent 开始或继续任务时会获得当前笔记和维护指引，也可以通过 MCP 的 `get_task_handoff`、`update_task_handoff` 读取和局部修改。自动维护依赖 Agent 实际调用工具，进程异常退出前未保存的内容不会自动补写。

维护指引要求交接笔记结构清晰、条理分明，并保持人类可读性：先概述当前状态，再用 Markdown 标题组织相关信息，以短段落或列表逐项说明，下一步按执行顺序排列。使用清楚易懂的语言，保留理解任务所需的上下文，不为压缩篇幅而堆砌缩写或省略必要说明。

编辑期间收到其他更新会提示并保留草稿；切换面板后可以继续编辑。保存失败时草稿也会保留。原片段已变更时需要基于最新内容修改，不会强行覆盖。当前版本不提供笔记历史回滚。

清理工作区不会删除交接笔记；项目归档后可查看和复制，恢复项目后可继续编辑。删除任务会同时删除其交接笔记。

## 任务描述建议

给 agent 的任务描述应包含：

- 目标
- 修改范围
- 不要改什么
- 验收方式
- 需要运行的测试或命令

不建议只写：

```text
修一下这个 bug
```

更好的写法：

```text
修复任务详情页切换项目后仍显示旧 session 日志的问题。

范围：
- 只改前端 session log store 和相关 hook
- 保持现有 UI 不变

验收：
- 增加或更新 store 测试
- 运行 pnpm --filter web lint
```

## 任务重试

任务可以 retry。重试会归档当前 workspace，并把任务重置为 `TODO`，方便用新的 workspace 重新执行。
